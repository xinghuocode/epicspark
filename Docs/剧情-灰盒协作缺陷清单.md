# 剧情核心 Agent ↔ 灰盒 Agent 协作缺陷清单（第二轮审计）

审计范围：`StoryAgent` / `StoryPrompt` / `StoryJson` / `StoryLayoutSpecBuilder` / `LayoutCoverage`
→ `GrayboxAgent` / `GrayboxToolSchema` / `GrayboxSpecExecutor` / `GrayboxSpecCompliance`
→ `BuildAgent` / `AssetBinding` → `SceneAssembler` / `GameDirector`。

每条都给出「现象 → 根因 → 修复 → 证据」。

| # | 现象（玩家/日志能看到） | 根因 | 修复 | 证据 |
|---|---|---|---|---|
| 1 | 灰盒"不听剧情" | 剧情只给散文，施工图靠正则重译：丢的东西灰盒无从执行 | 剧情 Agent 直接产出 `layoutSpec`（schema+提示词+解析），散文降级为解释 | 用例 A：`source=storyLayoutSpec+audit`，模型给的 zones/items/paths/npcs 逐条落地 |
| 2 | "高 12 米" 写了没用 | `height` 在 LayoutSpec → slot → PlacedAsset → 装配 四段里全被丢 | 四层都补 `height`，装配层有高度时按轴分别缩放 | 用例 A：城门槽位 h=12.0；远端抹掉后被还原 |
| 3 | NPC 站着不动 | 模型给 `layoutSpec.npcs[].name`，`npcPaths.npcId` 是它自编的 id，`SceneAssembler` 按真实 `npcId` 找不到 → 整条走位静默丢弃 | `ComposeNpcs` 按名字把动线对齐到真实 `npcId` | 用例 A：`plan.npcPaths[0].npcId == n_0`，起点 (13,5) |
| 4 | NPC 第一帧在别处、随后瞬移 | 站位取散文兜底位置，走位取 `layoutSpec`，两个来源 | 站位优先取 `spec.npcs` 走位起点 | 用例 A：NPC 槽位与动线起点同为 (13,5) |
| 5 | 场景里出现两根柱子 / 重复物件 | `AddMissingStoryUnits` 无条件为每个 prop 新增槽位，散文已把它写成地标 → 同点重叠两层 | 按名字/坐标去重，命中则把 `bindId` 挂到已有 item | 用例 A：`公告木柱` 只有 1 个槽位 |
| 6 | 调试记录里看不出"哪句是模型给的" | 施工图直接引用 `scene.layoutSpec`，补全就地改写模型的原始输出 | `CloneSpec` 深拷贝后再补全 | 用例 A：断言 `scene.layoutSpec.items.Count` 仍等于模型输出 |
| 7 | 模型给出的缺口被系统"好心"补掉 | 覆盖审计总是 repair：补项/改尺寸/改材质 | 施工图直给时 `repair=false`，只报 `gaps` + 合规串 | 用例 A：喷泉未进图 → `覆盖缺口 1`，且 spec 里确实没有喷泉 |
| 8 | 分区是否合并、动线是否被改，日志看不出 | `DescribePlan`/提示词不列 zones/npcPaths/height | 三处补全；`plannerNote` 标注"剧情施工图直给（未二次解析散文）" | 用例 A 输出的 plannerNote |
| 9 | 纯场地施工图被判"不可用" | `LayoutSpec.Usable` 只认 items | zones/paths 任一非空即可用 | 编译期 + 用例 A |
| 10 | 远端把高度/分区/动线改掉也能"合规通过" | 合规只比 items；`MergeRequired` 不还原 regions/npcPaths/height | 还原 regions/npcPaths/height 并记 deviation | 用例 A/B/C 远端抗命模拟：分区/动线/高度全部还原 |
| 11 | "北侧 (0,96) 是圣安东门" 被当成一个叫"北侧"的漏项 | 抽取器把方位词当实体名 | 方位词后接"是/有/为"才取后面名字，纯方位词不入库 | 用例 A：gap 只报真正的喷泉 |
| 12 | 流式分段搭出来的场景丢施工图引用 | `GameDirector.CloneSegment` 漏拷 `layoutSpec` | 补拷 | 代码审查 |
| 13 | 资产侧把 30×35 的教堂和 8×8 的门拉成同一比例 | 装配层一律等比缩放 | 有 height 时三轴分别缩放，无 height 时保持等比 | 代码审查 + 用例 A 高度断言 |

## 尚未处理（明确记录）

- **资产本身比例**：高度只约束外接盒，模型内部比例由检索到的 GLB 决定。
- **模型能否稳定产出 layoutSpec**：属提示词能力问题；实跑日志里 `[Story] 本幕没有给出可用的 layoutSpec` 即为未守约。
- **正则兜底链**：`StoryLayoutParser` 仍有 5 处静默 `return`，只在"模型没给 layoutSpec"的老路径上生效，本轮未动。
- **Unity 内 Play 回归**：本会话无法启动编辑器，需人工跑一次。
