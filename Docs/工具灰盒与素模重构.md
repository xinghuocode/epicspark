# 工具灰盒与强制素模重构

日期：2026-11-11

## 1. 目标与边界

本次重构针对“剧情写得很详细，但最终场景仍稀疏、混乱”的根因，不再用资产质量或加载速度掩盖空间布局问题。

当前正式链路：

```text
剧情 Agent
  输出详细 layoutDescription + 可选 layoutSpec 语义提示
  ↓（输入只读）
GrayboxAgent.PlanAsync
  ↓
GrayboxToolPipeline → GrayboxToolWorkspace
  define_zone / define_path / define_street / define_npc_route
  place_story_item / place_landmark / create_street_row
  decorate_zone / bind_anchor / bind_npc / bind_prop / finish_graybox
  ↓
严格校验，任何硬错误都阻断搭建
  ↓
SceneGenPipeline.PlaceAll → PrimitiveKit → SceneAssembler
```

**当前版本强制使用简单几何体。**美术库、GLB 加载、模型检索、运行时资产注册和 AI 资产生成均不参与正式游戏。

## 2. 数据契约

- `SceneSpec`：剧情需求，包含自然语言描述、剧情单位和可选语义提示。
- 输入 `LayoutSpec`：只读语义，不再是可被求解器就地改写的施工图。
- `GrayboxToolWorkspace.State`：独立的灰盒工具状态，所有位置、尺寸、朝向和绑定以它为准。
- `GrayboxPlan`：投影后的运行时灰盒，保存到 `SceneInstance.plan`，复用时按同一计划恢复锚点和 NPC。
- `BuildResult`：只能包含 `primitive != ""` 且 `modelId = prim:*` 的几何放置项。

所有 `LayoutItemSpec.size`、`GrayboxSlot.sizeX/sizeY`、`PlacedAsset.sizeX/sizeY` 均表示**世界 XZ 轴对齐包围盒**。`rotation/faceDir` 只表示立面方向；`PrimitiveKit` 在 ±90° 时交换本地建模尺寸，保证旋转前后世界占地一致。

## 3. 工具行为

### 区域与街道

- 区域级文字（例如“南侧居民区”）不会再被当成一栋巨型建筑。
- 只有道路/居民区语义时才生成连续街屋；空野外不会被自动围成城市。
- 连续排屋先切出合法沿街地块，再按开间分配单元；同组单元净隙必须在 `-0.05…0.20m` 内。
- 普通建筑不得侵入道路；城门/要塞只允许道路尽端搭接。
- 轴对齐街道使用沿街地块切分；斜向街道使用真实旋转占地（OBB）生成连续素模排屋。`SceneGenOBB` 与 `PrimitiveKit` 共用尺寸换算，道路净距和排屋连续性均按真实旋转几何校验。
- `none / dirt_path / trodden_path / path / trail / footpath` 是纯道路语义，不生成街屋，也不会触发“没有合法临街地块”的门禁。

### 地标

- 支持分区方位、朝向和显式 pinned 坐标。
- 无冲突时尊重点名位置；需要避让时由工具搜索附近合法位置并记录。
- 找不到合法位置时拒绝该工具并阻断最终场景，不再“试五次后仍强行放置”。
- 对旧解析器遗漏的 `名称：中心(x,z)、占地…、正立面…` 详细地标有专门恢复逻辑；建筑与入口锚点保持为两个关联对象。

### 广场、绿化、人群

- 广场/市场的绿化、路灯、人群由语义触发，不是每个区域都随机撒相同内容。
- 有聚集/抗议需求的区域会先保留中央开敞区，再计算临街排屋，避免房屋吃掉集会空间。
- 绿化和人群仍受场地边界、道路和已占空间约束。

### 剧情单位

- 合法显式锚点坐标优先保留。
- 锚点埋入建筑时才改找载体入口；边界城门会尝试门内侧。
- 不再通过修改 `SceneAnchorSpec.localPosition` 回写求解结果。
- 锚点时间推进与 `enter_anchor` 日志统一由 `GameDirector.HandleAnchorAsync` 执行一次。
- 场景复用使用缓存的 `SceneInstance.plan`，不再以 `null` 计划把锚点/NPC 放回固定角落。

## 4. 硬验收与失败行为

以下问题会阻止搭建，而不是只写日志后继续：

- 分区为空、构件重复 ID、构件出界；
- 普通建筑侵入道路、建筑互相重叠；
- 连续排屋重叠或出现非设计间隙；
- 剧情地标、锚点或 NPC 缺失；
- 锚点仍埋入建筑、NPC 航点仍位于建筑内；
- 搭建漏槽位，或结果混入非 `prim:*` 资产。

这意味着非法输入会得到明确失败提示。不要把“失败”当成需要隐藏的问题；它是防止错误场景进入游玩的门禁。

## 6. 剧情自定义场景尺寸

剧情 Agent 可以在每个场景的 `width` 与 `length` 中独立规定世界 X 宽度和 Z 纵深，单位为米。小型庭院、非正方形街区、大型战场不需要共用固定模板。

- 提示词不再限制 120…300 米；尺寸由剧情空间和内容需要决定。
- `StoryJson`、`GrayboxToolWorkspace`、`SceneGenProjector`、历史 `GrayboxPlanner` 统一使用 `EpicSpark.Core.SceneSize.SideOrDefault`。
- 不设置最大边长，不把大型场景夹回 500 米；只有 `NaN / Infinity / <=1 米` 等无效输入使用回退尺寸。
- 场地尺寸与几何复杂度分离：不能通过扩大面积来伪造内容密度，灰盒工具仍按合法空间和对象预算生成内容。
- 顶视调试相机的位置与远裁剪面会随场地尺寸调整。
- 离线回归覆盖 36×52 米小型非正方形场景和 800×1200 米野外战场；后者不生成城市排屋。
- Unity 真实剧情 JSON → 灰盒 → 素模装配验证为 **PASS**，报告见 `Logs/scenegen/report_20261112_141832.txt`；无建筑庭院不会被强制要求街屋。

## 7. 开发对照开关

- `EPICSPARK_SCENEGEN=0`：仅供开发者对照历史灰盒链路；不是正式质量回退。
- `EPICSPARK_PRIMITIVES=0`：**无效**。当前版本强制素模，避免测试与玩家进入不同资产路径。
- 历史 `SceneGenSolver` 暂保留作算法参照；正式 `GrayboxAgent` 默认不再调用它。
