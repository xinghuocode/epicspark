# 历史内容、剧情协议与来源追踪

日期：2026-11-12

## 1. 本次问题

巴格达与涿鹿的远端模型已经生成具有正确时代和地域的内容，但输出缺少一个收尾括号时，原实现先在 `OpenAIText.ExtractJsonObject` 阶段失败，导致 `JsonRepair` 无法执行，最终回退到固定的“关中·旧城广场”。

本地兜底又把粗粒度时代/地域识别、固定场景布局、固定 NPC/道具/流程和固定开场白组合起来，使不同事件表现出严重同质化。

## 2. 修复原则

### 任意自然语言输入

玩家不需要输入规范事件名，知识库也不需要预先收录完全相同的条目。LLM 可以直接理解任意事件并生成剧情、场景及内部结构。

结构化字段是系统内部的协作契约，不是用户输入限制。

### 修复先于丢弃

`StoryJson.ParseTurn` 在提取器因括号不平衡返回 null 时，会把原始文本交给 `JsonRepair`；修复成功才继续解析。`StoryJson.LastUsedRepair` 记录最近一次解析是否经过修复。

### 来源可追踪

`StoryTurn` 与 `StoryAgent` 记录：

- `RemoteAccepted`：远端内容直接通过；
- `RemoteRepaired`：远端内容修复后通过；
- `LocalFallback`：使用本地确定性内容；
- `fallbackReason`：具体回退原因。

场景录制的 `00_概要.txt` 会写入内容来源和兜底原因，不能再用最终场景名称反推是否发生替换。

### 诚实的历史兜底

没有可靠时代/地域依据时使用 `StoryEra.Unknown`：

- 不默认关中、法国大革命或某个城市；
- 场景名和叙述明确标注“离线未验证”；
- 通用开放几何场地只提供交互，不宣称为对应事件的史实复现；
- “知识库未收录该事件”的泛化相近资料不能用来给事件定型；
- 未被粗粒度中国/欧洲分类覆盖的地域保持未知，不强行归入其中。

### LLM 直接提供签名年份

每个场景可以返回 `startYear`：

- 公元后为正，例如巴格达陷落 `1258`；
- 公元前为负，例如涿鹿传说可用 `-2600`；
- 确实无法判断时为 `0`，显示“未知年代”，不再伪造成 1789；
- 持续推进时校正年份但保留已经过时间；
- 存档 `baseYear` 保存并恢复起始年，存档版本升级为 2；旧存档没有该字段时可使用场景年份或知识年份，不再硬编码 1789。

## 3. 不联网的验收探针

```powershell
Unity.exe -batchmode -nographics -quit -projectPath <工程> `
  -executeMethod EpicSpark.EditorTools.StoryContentProbe.Run `
  -logFile Logs\story-content-probe.log
```

探针使用假 `ILlmService`，不访问真实模型，覆盖：

1. 提示词中的示例 JSON 自身可解析；
2. 任意事件“涿鹿之战”的远端内容直接接受，不需要规范事件条目；
3. 巴格达输出缺少根对象收尾括号时完成修复，并保留 1258 年与巴格达内容；
4. 来源分别为 `RemoteAccepted` / `RemoteRepaired`；
5. 未知事件本地兜底不再出现关中，且明确声明不是史实复现；
6. 大事件知识卡片不能把巴格达子事件归入关中；
7. BCE 正确显示“公元前”，未知年代不再显示 1789，换幕保留已耗时。

报告写入 `Logs/story-content-report.txt`。2026-11-12 本次 Unity 2022.3.62f3c1 运行结果：**PASS**，未访问真实模型。

同一轮完整离线 Play Mode 冒烟（`EpicSparkSmokeTest.Run`）也为 **PASS / 0 error**，开局、锚点推进、复用、存档/读档与 NPC 均正常；报告见 `Logs/smoke.json`。已知法国大革命场景保持 1789 年，未知事件使用“未知年代”。

## 4. 边界

- 本地通用场景是诚实降级，不是通识历史理解能力；要获得事件级准确内容仍需 LLM 或可靠资料。
- 来源追踪能发现错误回退，但不能单独证明模型历史内容完全正确。
- 历史事实校验、知识库子事件覆盖与更细粒度的文化分类仍可持续加强。
- 几何工具和玩法门禁继续由 SceneGen/Play Mode 测试覆盖，不能用历史内容探针替代这些测试。
