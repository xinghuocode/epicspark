# 灰盒为什么不听剧情指挥：根因与契约化修复

## 一、结论

**灰盒没有抗命——它精确执行了 LayoutSpec；问题在于那份 LayoutSpec 不是剧情写的，而是"散文 → 正则/兜底列表"猜出来的翻译件。**

08:57:55 那次录制的硬证据（`...\debug\20261108_085755_s_3b3e2f12_0_c\`）：

| 观察 | 数值 | 说明 |
|---|---|---|
| `plannerNote` | `远端 LLM 灰盒工具调用完成 · 执行模式 · 槽位 20` | 最终计划来自远端灰盒 |
| `06.deviations` | 只有 3 条「远端重复定义的 road 已删除」 | **没有任何"被远端修改…已按规格恢复"** → 远端一步都没有越权 |
| 槽位 `specItemId` | 20/20 非空，规格外槽位 0 | 远端没有私自加工，也没有漏项 |
| `specCompliance` | `pass · 规格项 20 · 槽位 20` | 校验通过 |
| `04.layoutSpec` | `{items: [], paths: []}`（空对象） | 剧情 Agent **从未填过结构化布局**，施工图只能由散文重新编译 |
| 槽位 `regionId` | 20/20 为空串 | 分区归属从未传到槽位 |
| 分区 | 2 块，其中一块覆盖 x[-89.8,89.8] z[-99.8,50] | 散文写了 4 块地面，编译只剩 2 块 |
| `npcPaths` | 4 条，起点全是 spawn (0,-24) | 动线是按出生点合成的，不是剧情走位 |

也就是说：**"不听指挥"发生在"指挥"被写下来的那一刻**。
链路是 `剧情散文 → StoryLayoutParser(正则) → LayoutSpec → 灰盒`，正则丢的东西（喷泉直径、钟楼、4 块地面、边界墙、NPC 走位）根本不在 LayoutSpec 里；灰盒再忠实也只是忠实执行一份残缺的翻译件。而"合规"只比 `plan ↔ spec`（同一份翻译件的两端），所以永远报 pass。

补充结构性缺陷：

- `LayoutSpec` 只有 `items/paths`，**没有 zones / npcs / height** → 分区、动线、高度在类型层面就无法传递；
- 灰盒用两套解析：`regions/paths/npcPaths` 来自 `StoryLayoutPlanBuilder` 再解析一次散文，`slots` 来自 `LayoutSpec`，两份真相；
- `GrayboxSlot.regionId` 字段存在但无人赋值。

## 二、修复：一个编译器 + 一条投影链

原则：**散文只编译一次，编译结果（LayoutSpec）是唯一真相；灰盒只做投影，不再读散文。**

### 1) 类型补齐（`Assets/Scripts/Core/EpicSparkTypes.cs`）

```csharp
LayoutItemSpec.height                  // 剧情给的高度
LayoutZoneSpec   { zoneId, kind, description, polygon, groundHeight, required, source }
LayoutNpcSpec    { npcId, name, waypoints, loop, required }
LayoutSpec.zones / .npcs / .gaps / .diagnostics
```

### 2) 编译器收口（`StoryLayoutSpecBuilder.FinalizeSpec`）

散文 → `LayoutSpec` 时一并产出：

- **zones**：解析器认出的分区先进 spec，再由覆盖审计补它漏掉的（东侧泥土小巷、西侧铺石地），分区材质按散文纠正（石板广场曾被当 `water`）；
- **npcs**：起点用剧情坐标（散文坐标 → 锚点 → `localPosition`），不再从出生点合成；
- **base zone**：散文只写了广场周边时补一块覆盖全场的基底地面，保证北侧街屋/城门/锚点有分区归属；
- **地面项清理**：把"石板广场"这类被误当 Prop 的 70×70 巨物删掉（分区已承载）；
- **gaps**：散文写了但没有几何可落图的条目（如"边界由院墙围合、只有两个缺口"无坐标）**写进 spec.gaps**，不再静默；
- **diagnostics**：覆盖审计一行摘要。

### 3) 灰盒只做投影（`StoryLayoutPlanBuilder.TryBuild(..., LayoutSpec spec)`）

```
regions  ← spec.zones     （不再解析散文）
paths    ← spec.paths
npcPaths ← spec.npcs
slots    ← spec.items + regionId（包含关系，取最小分区）
```
`GrayboxSpecExecutor` 落槽后按多边形包含关系回填 `slot.regionId`。

### 4) 远端也必须听指挥（`GrayboxSpecCompliance`）

远端灰盒可以调用工具重定义分区/动线，但 `MergeRequired` 现在**强制还原**：

- `RestoreRegions`：按 `spec.zones` 重建 regions（远端把 4 块并成 1 块 → 恢复 4/5 块，记 deviation）；
- `RestoreNpcPaths`：按 `spec.npcs` 重建动线（远端把起点全改回 spawn → 恢复剧情起点，记 deviation）；
- 合规串变成 `pass · 规格项 18 · 槽位 18 · 覆盖审计[...]` 或 `· 覆盖缺口 N（首条缺口…）`，**"合规通过"再也盖不住漏项**。

回退开关：`EPICSPARK_COVERAGE=0`（关覆盖审计）、`EPICSPARK_LAYOUT_SPEC=0`（回旧链路）。

# 第二轮：把"最后一公里"补完（剧情 Agent 直出施工图 + 协作缺陷清理）

## 一、为什么还要改

第一轮让灰盒只投影 `LayoutSpec`，但 `LayoutSpec` 当时仍由**散文正则编译**得到——指挥链还是"二手"的：
模型写散文 → 正则猜 → 施工图 → 灰盒。正则猜不出来的东西（高度、走位、分区细节）依旧会丢。
结论：**必须让剧情 Agent 直接产出 `layoutSpec`**，散文降级为"给人看的解释"。

## 二、这轮改了什么

### 1) 剧情 Agent 直出 layoutSpec（契约层）

- `StoryPrompt`：工具 schema 增加 `layoutSpec`（zones / items / paths / npcs），并新增 7 条硬规则：
  zones 铺满场地、items 覆盖所有地物（含锚点载体）、paths 用 `"x,z;x,z"` 折线、npcs 给走位、
  anchors/npcs/props 也要带 `x/z`、不许写"约"。输出示例同步更新。
- `StoryLayoutSpecJson`（新）：模型输出 → `LayoutSpec` 的宽容解析（缺省/大小写/全角标点/中文 kind/
  坐标越界钳制/数量上限 120 项），解析不出内容返回 null。
- `StoryJson`：`scene.layoutSpec` 落地；anchors/npcs/props 的 `x/z` → `localPosition`。
- `StoryAgent.ParseAndValidate`：layoutSpec 是可选契约——空壳静默丢弃并告警，**不会因为缺它丢掉整幕剧情**。

### 2) 覆盖审计改为"只审计、不改写"（不再替模型改图）

`LayoutCoverage.Apply(..., repair)`：施工图由剧情直给时 `repair=false`，
丢的东西只进 `spec.gaps` 并出现在合规串上（`覆盖缺口 N（…）`），**不再静默补项/改尺寸/改材质**。
散文链路（老数据）仍保留 repair=true，向后兼容。

### 3) 高度贯通（剧情 → 施工图 → 槽位 → 资产 → 场景）

`LayoutItemSpec.height` → `GrayboxSlot.height`（新增）→ `PlacedAsset.height`（新增）→
`SceneAssembler`：有高度时按 `scaleX/scaleY/scaleZ` **分开缩放**，没高度时保持等比缩放。
回退链路 `CopyPlanSeed` / `CloneSlot` / `MergeRequired` 全部带上 height（远端抹掉也会被还原）。

### 4) 协作缺陷清理（详见 `Docs/剧情-灰盒协作缺陷清单.md`）

- NPC 动线绑定真实 `npcId`（模型自编 id 会被对齐，否则 `SceneAssembler` 找不到 NPC，走位静默失效）；
- NPC 站位 = 走位起点（消除"第一帧站在别处、随后瞬移"）；
- 占位道具去重（散文已写的地标不再叠一层 Prop 槽位）；
- 施工图深拷贝（补全不再就地改写 `scene.layoutSpec`，调试记录能区分"模型给的"和"系统补的"）；
- `LayoutSpec.Usable` 承认 zones/paths（纯场地施工图也算可用）；
- 灰盒提示词/`DescribePlan` 补上 zones、npcPaths、height、分区名（远端才看得见约束）；
- `plannerNote` 明确标注"剧情施工图直给（未二次解析散文）"，日志一眼可查模型是否守约；
- 方向词（"北侧 (0,96) 是圣安东门"）不再被当成漏项实体。
