# 素模生成链路：实施与验收

> 目标：把「生成场景」从"模型直接摆坐标"改成"模型给语义骨架 → 代码算几何/密度 → 只搭程序化几何体"。
> 本阶段**不使用任何美术资产库**（GLB / 模型库 / 资产生成服务），全部用长方体、圆柱、圆锥、球、胶囊、台阶堆叠。
> 目的：先把「密度 / 秩序 / 落位」验证干净，再回头接资产。

---

## 1. 新的生成链路

```
剧情 LLM
  └─ layoutSpec（语义骨架，不含坐标）
        zones[]      : name / kind / x1,z1,x2,z2 / openness / material
        streets[]    : name / nodes "x,z;x,z" / width / frontageBoth / style / depth / floors
        landmarks[]  : name / kind / on="分区名 方位" / facing / width / depth / height
                       / pinned+x,z（只有"必须原地"时才给）/ anchorFor
        items[]      : 可选，剧情点名物（有明确坐标）
        npcs[]/paths[]: 可选
  ↓
StoryLayoutSpecBuilder   （SceneGen 模式跳过旧"审计/补齐/Clamp/Sort"）
  ↓
SceneGenSolver.Solve()   ← 确定性求解器（纯几何，无随机布局）
  ① NormalizeZones     分区归一 + 未覆盖区域补"场地基底"
  ② CollectStreets     由 paths(kind=road) 的折线推出街段
  ③ AddPinnedItems     点名物落位 + 排屋按世界 AABB 重排
  ④ AddSemanticLandmarks  只按 "分区 + 方位" 贴边，不占道路
  ⑤ FillFrontage      沿街两侧按"开间=地块长度/单元宽"连续排屋
  ⑥ FillEmptyZones    街区四边围合（进深随分区尺度自适应）
  ⑦ EnsureEnclosure   只在街口留缺口的边界墙
  ⑧ ScatterZoneProps  路灯/树/人群/摊位
  ⑨ AddStoryUnits     锚点挂到载体正前方；NPC/道具避让建筑
  ⑩ DropBadSolverUnits / NormalizeAnchors / Measure   KPI + 门禁
  ↓
SceneGenProjector.Project()   LayoutSpec → GrayboxPlan（槽位只带 AABB + faceDir）
  ↓
SceneGenPipeline.PlaceAll()   槽位 → PlacedAsset（primitive=row_house/church/gate/...）
  ↓
PrimitiveKit.Build()          程序化几何体（长方体/圆柱/圆锥/…），美术库完全不参与
```

远端灰盒 LLM 在 SceneGen 模式下**不再被调用**（它此前会把施工图重新摆一遍，这正是"每次都不一样/零散"的来源）。
若求解器异常或产出为空，才回退到旧的 LayoutSpec 执行器 / 远端口语规划链路。

## 2. 必须守住的几何不变量

| 不变量 | 实现位置 | 说明 |
| --- | --- | --- |
| 尺寸语义唯一 | `LayoutItemSpec.size` / `GrayboxSlot.sizeX,sizeY` / `PlacedAsset.sizeX,sizeY` | 全部是**世界 XZ 轴对齐包围盒**；`rotation`/`faceDir` 只表示立面朝向，绝不交换 x/z 尺寸 |
| 旋转后占地仍正确 | `PrimitiveKit.Build` | 本地建模以 +Z 为正立面；旋转 90° 时把本地 X/Z 尺寸对调，保证世界 AABB 不变 |
| 排屋无缝 | `FillFrontage` | 开间 = `(段长 - (n-1)*rowGap)/n`，先算 n 再定开间，天然无缝隙；n = floor((段长+gap)/(单元宽+gap)) |
| 临街不侵入道路 | `FillFrontage` / `AddSemanticLandmarks` | 街道走廊先切掉再排屋；地标只在"道路穿过"时平移避让，街端 T 接要塞/城门是允许的 |
| 锚点不猜坐标 | `AddStoryUnits` + `SceneGenProjector` | 锚点位置 = 载体中心 + 立面法线 × 半深 + 1.6m；`SceneAssembler.ResolveAnchorPosition` 优先读计划槽位 |
| 无空分区 | `FillEmptyZones` | 住宅/教堂/市场分区至少一圈围合街屋；广场用道具，不用房子硬填 |
| 确定性 | `SceneGenRng`（splitmix64，种子 = hash(sceneId+sceneName)） | 同一 sceneId 两次求解 byte-equal |

## 3. 验收 KPI（200×220m 测试城）

| 指标 | 旧链路实测 | 新链路实测 | 目标 |
| --- | --- | --- | --- |
| 建筑占地密度 | 10.7% | **26%** | 25–35% |
| 临街连续度 | ≈33% | **91%** | ≥80% |
| 边界围合度 | — | **94%** | ≥90% |
| 建筑重叠对数 | 8 | **0** | 0 |
| 空分区数 | 4 | **0** | 0 |
| 出界构件 | — | **0** | 0 |
| 锚点绑定 | 2/4（且被挪走 10–14m） | **3/3，偏差 ≤1.6m** | ≤0.5m（待接载体真实门口后再收紧） |
| 首次呈现槽位 | 12/30（按 60m 分段） | **全部 199 个一次落地** | 100% |
| 求解确定性 | 否 | **是（两次 byte-equal）** | 必须 |

补充场景：

- 极简 60×60 单街一区：建筑 24 间、密度 52%、临街 100%、围合 93%、冲突 0、空分区 0 → PASS。
- 空输入（模型没给 `layoutSpec`）：自动补 1 个基底分区 + 18 个构件，不崩、不空场 → PASS。

> 说明：小屋群（60×60）一圈进深的占地比例天然偏高，所以小场景密度上限放宽到 60%；
> 25–35% 的目标只适用于 100m 以上的城区。

## 4. 代码位置

| 文件 | 作用 |
| --- | --- |
| `Assets/Scripts/SceneGen/SceneGenGeometry.cs` | Rect/线段/朝向工具，RNG（splitmix64） |
| `Assets/Scripts/SceneGen/SceneGenSolver.cs` | 确定性求解器 + `SceneGenReport` KPI |
| `Assets/Scripts/SceneGen/SceneGenProjector.cs` | LayoutSpec → GrayboxPlan |
| `Assets/Scripts/SceneGen/PrimitiveKit.cs` | 程序化几何体（建筑/教堂/城门/要塞/台阶/摊位/灯/树/人群…） |
| `Assets/Scripts/SceneGen/SceneGenPipeline.cs` | 门面：Solve / Plan / PlaceAll |
| `Assets/Scripts/Core/EpicSparkTypes.cs` | `LayoutStreetSpec`、`LayoutLandmarkSpec`、`openness/material`、`primitive/faceDir`、`sceneGenReport` |
| `Assets/Scripts/Story/StoryPrompt.cs` | 新的语义 `layoutSpec` schema（zones/streets/landmarks，无坐标） |
| `Assets/Scripts/Story/StoryLayoutSpecJson.cs` | 新 schema 的解析（streets/landmarks） |
| `Assets/Scripts/Story/StoryLayoutSpecBuilder.cs` | SceneGen 模式跳过旧审计/补齐 |
| `Assets/Scripts/Graybox/GrayboxSpecExecutor.cs` | 顶部接入求解器（失败回退旧链路） |
| `Assets/Scripts/Graybox/GrayboxAgent.cs` | 求解器直出后不再调用远端灰盒；跳过旧"规格合规"误报 |
| `Assets/Scripts/Build/BuildAgent.cs` | 素模短路：不查模型库 |
| `Assets/Scripts/Loading/SceneAssembler.cs` | 按 primitive 建模型；素模不补灰盒棚架 |
| `Assets/Scripts/Loading/SceneLoadingSequence.cs` | 素模按根节点显隐（否则只隐藏第一个 renderer） |
| `Assets/Editor/SceneGenProbe.cs` | 编辑器内验收探针（batchmode 可用） |

## 5. 开关（默认全开）

| 环境变量 | 默认 | 作用 |
| --- | --- | --- |
| `EPICSPARK_SCENEGEN` | 1 | 用确定性求解器替代旧灰盒/远端摆位 |
| `EPICSPARK_PRIMITIVES` | 1 | 素模搭建（不查美术资产库） |
| `EPICSPARK_SCENEGEN_GATE` | 1 | KPI 门禁（剔除严重重叠单元并记录，不静默） |

关掉任一开关即回退旧链路，便于 A/B 对比（旧代码没有删除）。

## 6. 怎么验收

### 6.1 编辑器内（推荐，需要能启动 Unity）

```
Unity.exe -batchmode -quit -projectPath D:\unityproject\epicsparktest4 \
  -executeMethod EpicSpark.EditorTools.SceneGenProbe.Run -logFile -
```

探针会：造一个 200×220m 测试城 → 求解两次做确定性对比 → 打印 KPI/排屋不变量/锚点距离 →
写 `Logs/scenegen/report_<时间戳>.txt` 与 `solved_<时间戳>.json`，PASS 退出码 0，FAIL 退出码 2。

### 6.2 无 Unity（离线探针）

`scenegen_harness/Program.cs` 用 Unity 安装目录里的托管 DLL 直接跑求解器（不依赖编辑器）：

```powershell
$u='D:\unityanzhuang\2022.3.62f3c1\Editor\Data'
$src = (Get-ChildItem 'Assets\Scripts\Core','Assets\Scripts\SceneGen' -Filter *.cs | % FullName) + 'scenegen_harness\Program.cs'
# 首次运行需把 $u\Managed\UnityEngine\*.dll 拷到 scenegen_harness\ 下
& 'C:\Program Files\dotnet\dotnet.exe' "$u\DotNetSdkRoslyn\csc.dll" -nologo -langversion:9.0 -target:exe `
  -out:scenegen_harness\harness.dll -nowarn:0649,0414 `
  "-r:$u\Managed\UnityEngine\UnityEngine.CoreModule.dll" `
  "-r:$u\Managed\UnityEngine\UnityEngine.PhysicsModule.dll" `
  "-r:$u\Managed\UnityEngine\UnityEngine.JSONSerializeModule.dll" `
  "-r:$u\Managed\UnityEngine\UnityEngine.IMGUIModule.dll" `
  "-r:$u\NetStandard\ref\2.1.0\netstandard.dll" $src
& 'C:\Program Files\dotnet\dotnet.exe' 'scenegen_harness\harness.dll'
```

### 6.3 游戏内看效果

主菜单选场景进入即可：日志里会出现
`[灰盒] SceneGen 求解器：… · 密度 26% · 临街连续 91% · …`、
`[搭建/素模] 槽位 N 个 → 构件 M 个（不含锚点/NPC）`，
随后 HUD 提示「正在用程序化几何体搭建场景（素模阶段，不含美术资产）…」。

## 7. 已知限制 / 下一步

1. **只在离线探针验证过 KPI**：本沙箱无法启动 `Unity.exe`（`Access is denied`），
   因此运行时（材质/相机/碰撞/加载四段动画）需要在编辑器里跑一次 `SceneGenProbe` 与一次真实进场景确认。
2. 锚点偏差目前 ≈1.6m（载体包围盒前沿 + 1.6m），接真实资产后应改用"载体门口锚点"。
3. `landmarks` 的方位若与街道冲突（例如主街正对广场北侧），当前策略是**沿边平移**而不是截断街道；
   若希望"教堂正好居中"，需要模型把主街节点收在广场边缘。
4. 街区围合是"一圈进深"，没有做院落/里坊细分；密度调优主要靠 `unitWidth/unitDepth/rowGap/setback` 四个常量。
5. 美术资产库代码未删除，仅通过 feature flag 从生成路径上摘掉，随时可对照回滚。
