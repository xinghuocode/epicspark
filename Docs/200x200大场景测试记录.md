## 2. 这次大场景暴露并修掉的问题

### 2.1 60 米硬上限把 70 米集市棚削成 60 米

200×200 场景里的 `集市木棚` 是 `70×30` 米；第一次跑出来只有 `60×30`，合规校验报：

```
规格槽位 item_集市木棚_37 尺寸 60.0×30.0，规格 70.0×30.0
```

同一类 60 米硬上限散落在 5 个位置：

| 文件 | 位置 | 修正 |
|---|---|---|
| `Assets/Scripts/Graybox/GrayboxSpecExecutor.cs` | `BuildSlots` 槽位尺寸 | 按场景尺寸放宽到 `clamp(max(60, max(W,L)*0.9), 60, 180)` |
| `Assets/Scripts/Graybox/StoryLayoutPlanBuilder.cs` | 地标槽尺寸 | 同上 |
| `Assets/Scripts/Graybox/GrayboxPlanner.cs` | `Sanitize` / `Validate` | 同上 |
| `Assets/Scripts/Graybox/GrayboxSpecCompliance.cs` | `MergeRequired` / `Validate` 期望尺寸 | 新增 `MaxSpecSize(plan)` |
| `Assets/Scripts/Build/BuildAgent.cs` | `SanitizeSlot` | 同上 |

修完后 `集市木棚` 槽位为 **70×30**，合规重新通过。

### 2.2 `中央石板广场` 被当成 60×60 道具

`【地面】中央石板广场：……石灰岩方石铺地，范围(-40,-40)—(40,40)` 里的“石板”先命中了 `PropWords`，`ClassifyKind` 返回 `Prop`；而 `LooksLikeGround` 开头对 `Prop` 直接返回 false，于是广场没有成为地面分区，反而生成了一个 60×60 的道具槽，回退到 `mdl_sack_001`。

修复：

- `LooksLikeGround` 对带 `【地面】` 标签的句子不再因 `kind == Prop` 提前返回 false。
- `StoryLayoutParser` 在 `【地面】` 一句包含多个 `PointPair` 时，把每个矩形都 `AddZone`，避免只取第一个范围。

### 2.3 大场景流式加载会重复搭建

原流程：

1. `BuildAgent.BuildAsync` 对 `plan.slots` **全部**搭建；
2. `SceneAssembler.AssembleAsync` 全部落位；
3. 因为 `segmentCount > 1`，`StreamRemainingSegmentsAsync` 又从第 1 段开始，把 `segment >= 1` 的槽位再搭一遍并 `AppendModelsAsync`。

结果是大场景（200×200 为 4 段）会把第 1–3 段的模型追加两次。

修复（`Assets/Scripts/Bootstrap/GameDirector.cs`）：

- 首次搭建只传 `CloneSegment(plan, 0)` 给 `BuildAgent`；
- `SceneAssembler` 仍用完整 `plan` 生成地面/道路/边界和锚点；
- 其余段继续由 `StreamRemainingSegmentsAsync` 追加；
- `CloneSegment` 补拷 `specDriven`、`layoutShift`，避免子计划失去规格驱动信息。

该修复已编译通过；本次离线审计本身不经过 `GameDirector`，所以“不重复”是代码路径检查 + 分段统计，不是 Play 模式实测。

## 4. 仍然存在的限制

1. **资产层仍是短板**：`Services.AssetGenerator 未装配`，市政厅/官署/教堂都回退到 `mdl_church_001`，集市棚回退到 `mdl_lantern_001`。结构位置正确，但外观不匹配。
2. **剧情规格自身有道路冲突**：市政厅、圣安东门、教堂、官署都提示侵入道路净宽；这是 LayoutSpec 同时要求“道路居中 + 建筑压线”造成的，执行器只能提醒，不能自动改剧情。
3. **地面分区只有 2 个**：200×200 布局里写了 4 块铺装，当前解析只稳定产出 2 个；不影响建筑落位，但地面材质分区还不完整。
4. **排屋语义名退化**：南侧排屋在部分分支里变成 `沿街_1_1…`，位置和数量正确，名字不够可读。
5. **尚未做远端灰盒实测**：本次是确定性执行器 + 离线审计；远端 LLM 不可用/不合规时本来就会走这条路径，但这不代表远端工具调用也稳定。
