# EpicSpark · 局域网展示端（实时摄像头画面）

> 目标：**游戏本体**（Unity 2022.3，本仓库）与**展示端**（另一台设备/另一块屏幕）在同一个局域网内。
> 游戏本体启动后自动暴露只读接口；展示端自动在局域网里找到游戏，实时显示游戏内**主摄像头（玩家视角，下称「中摄像头」）**的画面。
>
> 本文件同时是**协议契约**：`Assets/Scripts/Streaming/`（游戏端实现）与 `Viewer/`（展示端实现）必须严格按本文件实现。

---

## 1. 总体结构

```
┌───────────────────────────── 游戏本体设备 ─────────────────────────────┐
│  Unity 游戏（EpicSpark）                                                │
│   ├─ 主摄像头（玩家视角 = "中摄像头"）                                  │
│   │    └─ LanDisplayCapture：克隆主相机 → RenderTexture → JPEG（15 fps） │
│   ├─ LanDisplayHttpServer：TCP 45231                                     │
│   │    ├─ GET /                 自检页（浏览器直接看）                   │
│   │    ├─ GET /api/info         设备/相机/采集状态                       │
│   │    ├─ GET /snapshot.jpg     单帧快照                                 │
│   │    └─ GET /stream.mjpg      MJPEG 实时流                             │
│   └─ LanDisplayDiscovery：UDP 45230（每 2 s 广播 beacon + 应答探测）     │
└──────────────────────────────────────────────────────────────────────────┘
                    ▲ UDP 广播 / HTTP 拉流（同一局域网，无需任何配置）
┌───────────────────┴───────────────────────── 展示端设备 ─────────────────┐
│  Viewer（Python 3 标准库，单进程）                                       │
│   ├─ udp_discovery：监听 45230 收 beacon，并主动广播探测                 │
│   ├─ subnet_sweep：广播被防火墙拦住时，扫本机 /24 的 45231/api/info      │
│   ├─ local_http_server：127.0.0.1:8686 提供网页 + 发现 API + MJPEG 代理  │
│   └─ 浏览器/全屏窗口：自动连上第一台游戏，实时播放画面，断线自动重连     │
└──────────────────────────────────────────────────────────────────────────┘
```

设计约束：

- **只读**：游戏端只发画面与状态，不接受任何写操作、不执行远端指令。
- **零第三方依赖**：游戏端只用 Unity 原生 API + .NET 标准库；展示端只用 Python 标准库（mock 工具除外）。
- **零配置发现**：同一网段下双方不需要填 IP；跨网段/防火墙拦截时可用 `--game <ip>` 手动指定。

## 2. 端口

| 用途 | 协议 | 端口 | 配置（游戏端环境变量） |
|---|---|---|---|
| 设备发现 | UDP | **45230** | `EPICSPARK_DISPLAY_UDP_PORT` |
| 画面/状态接口 | TCP(HTTP) | **45231** | `EPICSPARK_DISPLAY_HTTP_PORT` |
| 展示端本地网页 | TCP(HTTP) | **8686** | `--http-port`（展示端） |

端口被占用时游戏端自动顺延（HTTP 端口 +1 最多试 20 个），并把**实际端口**写进 beacon，展示端必须用 beacon 里的端口而不是写死 45231。

## 3. 发现协议（UDP 45230）

### 3.1 游戏端 → 广播 beacon

游戏端每 **2 s** 向 `255.255.255.255:45230` 广播一次 UTF-8 JSON（同时向接收到的探测包单播回复同一份 JSON）。
单包 ≤ 1024 字节。

```json
{
  "svc": "epicspark.display",
  "v": 1,
  "id": "epi-7f3a91c2",
  "name": "EpicSpark · DESKTOP-ABC",
  "game": "EpicSpark",
  "http": 45231,
  "udp": 45230,
  "stage": "playing",
  "scene": "法国大革命",
  "camera": { "id": "main", "name": "主摄像头（玩家视角）" },
  "cameras": [
    { "id": "main", "name": "主摄像头（玩家视角）", "width": 960, "height": 540 }
  ],
  "ts": 1762570000123
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `svc` | string | 固定 `"epicspark.display"`，展示端据此过滤 |
| `v` | int | 协议版本，当前 `1` |
| `id` | string | 设备 ID，进程生命周期内稳定（重启可变化） |
| `name` | string | 人类可读名（含机器名） |
| `game` | string | 固定 `"EpicSpark"` |
| `http` | int | HTTP 接口实际监听端口 |
| `udp` | int | 发现端口（即本包发出的端口） |
| `stage` | string | 游戏阶段：`title` / `generating` / `playing` / `paused` |
| `scene` | string | 当前场景/事件名，空串表示标题界面 |
| `camera` | object | 默认摄像头（`/stream.mjpg` 不指定 `camera` 时用它） |
| `cameras` | array | 摄像头列表，每项 `id/name/width/height`；v1 只有一项 |
| `ts` | int | 发送时刻 Unix 毫秒 |

### 3.2 展示端 → 探测

展示端每 **2 s** 向 `255.255.255.255:45230` 发送 ASCII 探测包：

```
EPICSPARK_DISCOVER 1
```

游戏端收到后，向来源地址**单播**回复一份 beacon JSON（内容同上）。

### 3.3 兜底：子网扫描

展示端连续 **5 s** 没收到任何 beacon 时，对每个本地 IPv4 网卡的 `/24` 网段并发请求
`http://<ip>:45231/api/info`（也可用 `--scan-ports 45231,45232,...` 指定候选端口），
返回合法 `svc == "epicspark.display"` 的 JSON 即视为找到设备。
扫描每 15 s 重试一次，直到发现设备或用户手动指定。

## 4. HTTP 接口（游戏端，端口见 beacon）

所有响应都带：

```
Access-Control-Allow-Origin: *
Cache-Control: no-store, no-cache
```

`OPTIONS *` 返回 `204` 并带 `Access-Control-Allow-Methods: GET, OPTIONS`
（展示端用代理拉流，CORS 只用于浏览器直连调试）。

### 4.1 `GET /api/info`

```json
{
  "svc": "epicspark.display",
  "v": 1,
  "game": "EpicSpark",
  "id": "epi-7f3a91c2",
  "name": "EpicSpark · DESKTOP-ABC",
  "host": "192.168.31.20",
  "startedAt": "2026-11-08T04:10:00.123Z",
  "uptimeSec": 12.3,
  "stage": "playing",
  "scene": "法国大革命",
  "ports": { "http": 45231, "discovery": 45230 },
  "cameras": [
    { "id": "main", "name": "主摄像头（玩家视角）", "width": 960, "height": 540 }
  ],
  "capture": {
    "cameraId": "main",
    "mode": "dedicated",
    "width": 960,
    "height": 540,
    "targetFps": 15,
    "actualFps": 14.6,
    "jpegQuality": 75,
    "frames": 321,
    "lastFrameAgeMs": 62,
    "lastError": null
  },
  "stream": {
    "mjpeg": "/stream.mjpg",
    "snapshot": "/snapshot.jpg",
    "boundary": "epicsparkframe"
  },
  "clients": { "streaming": 1, "total": 3 }
}
```

### 4.2 `GET /api/health`

`200` + `{"ok":true,"svc":"epicspark.display","v":1}`；用于扫描与连通性判断。

### 4.3 `GET /snapshot.jpg`

返回最近一帧 JPEG（`Content-Type: image/jpeg`）。
还没有任何帧时返回 `503` + `{"error":"no_frame"}`。

### 4.4 `GET /stream.mjpg`

`Content-Type: multipart/x-mixed-replace; boundary=epicsparkframe`，每个 part：

```
--epicsparkframe\r\n
Content-Type: image/jpeg\r\n
Content-Length: <字节数>\r\n
X-Seq: <帧序号，从 1 递增>\r\n
X-Frame-Utc-Ms: <该帧采集时刻 Unix 毫秒>\r\n
\r\n
<jpeg 二进制>\r\n
```

- 新帧产生就推送；同一帧不重复推。客户端跟不上就自然丢帧（服务端只发最新帧，不排队）。
- 查询参数（v1 全部可选，服务端可忽略不支持的项）：
  `camera=<id>`（必支持）、`fps=<1-30>`（该连接的推送上限）、`quality=<20-95>`、`width=height=`（尺寸建议，服务端按采集配置为准）。
- 连接断开/客户端超时由服务端回收；同一时刻最多 **8** 路流，超出返回 `503`。
- 无新帧时可每 500 ms 发送一个极小的 1×1 JPEG 保活帧（可选实现）。

### 4.5 `GET /`

自检页：内嵌 `<img src="/stream.mjpg">` + 轮询 `/api/info` 的状态文字（设备名、摄像头、fps、帧数）。
没有展示端时，用游戏本机浏览器打开 `http://127.0.0.1:<http端口>/` 即可验证接口是否正常。

## 5. 采集与编码（游戏端实现要点）

- 采集对象：**主摄像头**（`Camera.main`，即玩家视角；找不到时用 `FindObjectOfType<Camera>()`）。
  v1 的相机 `id` 固定为 `main`，名称「主摄像头（玩家视角）」；列表结构已为多机位预留。
- 采集方式：**独立采集相机**克隆主相机参数（位置/朝向/FOV/裁剪面/清除方式/天空盒），
  渲染到独立 `RenderTexture`（默认 960×540），**不影响玩家屏幕与 HUD**。
  每帧只在采集节拍开启一帧（`WaitForEndOfFrame`）→ `ReadPixels` → `ImageConversion.EncodeToJPG(quality)`。
- 默认 **15 fps**、JPEG 质量 **75**，可配置；主线程编码开销约 2–6 ms/帧（960×540），
  可在 Inspector 或环境变量里降低分辨率/帧率/质量。
- 线程模型：采集/编码在**主线程**；TCP/UDP/编码后的 JPEG 分发在后台线程。
  后台线程**绝不触碰 UnityEngine 对象**，只读 `byte[]` 帧缓存与纯数据快照。
- 失败兜底：采集相机不可用（例如某些 SRP/无头环境）时自动切到 `ScreenCapture` 方式
  （环境变量 `EPICSPARK_DISPLAY_CAPTURE=screen` 可强制），并在 `/api/info.capture.lastError` 与日志里说明。
- 退出时（`OnDestroy`/`OnApplicationQuit`）停止广播、关闭监听与所有连接，日志打印实际地址。

### 5.1 配置（游戏端）

启动时自动创建（无需改场景）。默认值如下，均可被环境变量覆盖：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `EPICSPARK_DISPLAY` | `1` | `0`/`off` = 完全关闭展示端接口 |
| `EPICSPARK_DISPLAY_HTTP_PORT` | `45231` | HTTP 端口（占用则顺延） |
| `EPICSPARK_DISPLAY_UDP_PORT` | `45230` | 发现端口 |
| `EPICSPARK_DISPLAY_FPS` | `15` | 采集帧率（1–30） |
| `EPICSPARK_DISPLAY_WIDTH` / `_HEIGHT` | `960`/`540` | 采集分辨率 |
| `EPICSPARK_DISPLAY_QUALITY` | `75` | JPEG 质量（20–95） |
| `EPICSPARK_DISPLAY_CAMERA` | `main` | 采集的相机名/标签（默认主相机） |
| `EPICSPARK_DISPLAY_NAME` | `EpicSpark · <机器名>` | 展示端显示的名称 |
| `EPICSPARK_DISPLAY_CAPTURE` | `dedicated` | `dedicated` / `screen` |
| `EPICSPARK_DISPLAY_VERBOSE` | `0` | `1` = 打印每个 HTTP 请求 |

也可以在场景里手动给任意对象挂 `LanDisplayServer` 组件，用 Inspector 覆盖上述默认值。

## 6. 展示端（`Viewer/`，Python 3.8+，仅标准库）

```
python Viewer/epicspark_viewer.py                # 自动发现 + 打开浏览器（默认 http://127.0.0.1:8686）
python Viewer/epicspark_viewer.py --game 192.168.31.20:45231   # 手动指定，跳过扫描
python Viewer/epicspark_viewer.py --no-browser   # 只开本地服务（投屏/Kiosk 用）
python Viewer/epicspark_viewer.py --list         # 只发现并打印设备，不启动网页
```

Windows 下双击 `Viewer/run.bat` 亦可。

行为：

1. 起本地 HTTP 服务（默认 8686），自动打开浏览器；页面为全屏友好的深色监控墙风格。
2. 后台同时跑 UDP 监听 + 主动探测；5 s 内没发现设备则子网扫描；找到后**自动连接第一台**。
3. 通过本地代理拉 `stream.mjpg` 并原样转成 MJPEG 给页面（同源、无 CORS、可显示统计）。
4. 游戏重启/掉线/换场景：自动重连（1 s→8 s 退避），页面显示「正在寻找游戏…」而不会白屏。
5. 页面支持：F 全屏、R 重新扫描、D 设备列表、点击设备切换、断线提示。

展示端本地 API（页面用，也可脚本调用）：

| 方法/路径 | 说明 |
|---|---|
| `GET /api/devices` | `{"devices":[{beacon...,"ip":"…","lastSeenMs":…,"source":"udp\|sweep\|manual","active":true}],"active":{…}\|null}` |
| `POST /api/select` | body `{"ip":"192.168.31.20","httpPort":45231}`，切换/锁定目标 |
| `POST /api/rescan` | 清空设备表并立即重新扫描 |
| `GET /api/status` | 展示端状态：发现方式、目标设备、流状态（`connecting/live/error`）、fps、累计字节、最后错误 |
| `GET /api/proxy/stream.mjpg` | 代理后的 MJPEG 实时流 |
| `GET /api/proxy/snapshot.jpg` | 代理后的单帧快照（封面/重连时用） |

## 7. 验收标准

1. **游戏端**：Play 后 3 s 内本机浏览器打开 `http://127.0.0.1:45231/` 能看到实时画面；`/api/info` 返回合法 JSON。
2. **展示端**：在同一台机器（回环）或同网段另一台设备上启动，**无需填 IP** 在 10 s 内自动找到游戏并出画面。
3. **实时性**：15 fps 采集下展示端画面延迟 ≤ 500 ms（同网段），连续播放 5 分钟不中断。
4. **鲁棒性**：杀进程/重启游戏/切换场景后，展示端自动恢复；UDP 广播被防火墙拦时子网扫描仍能找到。
5. **零污染**：展示端只在游戏端读取数据，不改变游戏状态；关闭展示端不影响游戏。
6. **可验证**：`Viewer/tools/mock_game.py` 在无 Unity 环境下模拟游戏端协议，`Tools/verify_display.py` 自动跑通发现 → 拉流 → 页面截图。

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 展示端点「重新扫描」仍找不到 | 两台设备不在同一网段 / AP 隔离 / Windows 防火墙拦了 UDP 45230 | ① 确认同网段；② 手动 `--game <ip>:45231` 直连；③ 首次启动游戏时在防火墙弹窗选「允许专用网络」 |
| 找到设备但一直「连接中」 | 游戏端 HTTP 端口被防火墙拦（TCP 45231） | 放行端口；或在游戏端用 `EPICSPARK_DISPLAY_HTTP_PORT` 换端口 |
| 画面全黑 | 采集相机渲染异常 / 游戏处于暂停（编辑器暂停） | 看 `/api/info.capture.lastError`；设 `EPICSPARK_DISPLAY_CAPTURE=screen` 走屏幕捕获 |
| 画面卡顿 | 采集分辨率/质量过高，主机 GPU 吃力 | 降 `EPICSPARK_DISPLAY_WIDTH/HEIGHT/FPS/QUALITY` |
| 端口被占用 | 上一次进程没退干净 | 重启游戏；或看日志里实际端口（会自动顺延） |

## 9. 已知限制

1. 只传画面不传声音（v1）；音轨/多机位/鼠标键盘反控属于后续扩展。
2. MJPEG 未加密、无鉴权，**仅限可信局域网**使用；不要暴露到公网。
3. 采集是额外一次场景渲染（只在采集节拍），会带来少量 GPU/CPU 开销；关闭接口（`EPICSPARK_DISPLAY=0`）可完全消除。
4. 同一局域网内多台游戏主机时，展示端按发现顺序自动连第一台，可在设备列表里手动切换。
