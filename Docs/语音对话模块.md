# EpicSpark · NPC 语音对话模块

> 适用引擎：**Unity 2022.3.62f3c1（URP 14.0.12）**，以 Windows 桌面为主
> 代码位置：`Assets/Scripts/Voice/`、`Assets/Scripts/UI/VoiceDialoguePanel.cs`、`Assets/Scripts/Npc/Runtime/NpcDialogueTrigger.cs`
> 配置：`Assets/StreamingAssets/VoiceConfig.json`（工程里已配置一把百炼 Key，本文不写明文，日志中显示为 `sk-****`）
> 自检：`EpicSpark.EditorTools.EpicSparkVoiceSelfTest` → `Logs/voice-selftest.json`

---

## 1. 模块定位

一句话：给 EpicSpark 的 NPC 对话加一层「**按住 V 说话 → 实时识别 → NPC 大模型回复 → 语音朗读**」，并提供「**打字对话**」作为全程兜底。

- 语音只负责**两端**：语音识别（ASR）与语音合成（TTS），走阿里百炼 DashScope 的 WebSocket。
  NPC 说什么、怎么记住上下文，仍由 EpicSpark 自己的 `NpcDialogueService` / `ILlmService` 决定。
- 对话的「会话、历史、回复广播」由 `NpcDialogueTrigger` 负责；语音控制器只是它的一个客户端，
  只依赖它的静态事件与公开方法，**不直接改 NPC 模块内部状态**。
- 全链路可降级：没有语音 Key、没有麦克风、ASR / TTS 失败时，都能继续用键盘与 NPC 对话；
  语音模块整体不工作也不影响原有玩法（这点与四层 Agent 的离线兜底一致）。

语音 Key 与 LLM Key 是**两套**：ASR/TTS 用百炼（DashScope）Key，NPC 回复用游戏内「设置 API Key 与模型」（F10）里配置的 LLM Key。

## 3. 玩法与按键

1. 距 NPC **3 米内**（`TalkRange`）按 **F** 开始对话：玩家输入被禁用，底部弹出语音对话面板，NPC 先说一句开场白。
2. 面板常驻显示 NPC 名、状态行、玩家台词、NPC 台词、输入框与「发送」按钮、操作提示与麦克风音量条。
3. **按住 V 说话，松开 V 结束**：录音期间面板实时显示识别结果（提交前末尾标「（识别中）」）；
   松开后发送给 NPC，状态变为「思考中」，NPC 回复到达后显示并朗读。
4. 没有麦克风 / 没有语音 Key / 识别失败时，按 **T** 聚焦输入框，用键盘打字对话（支持中文输入法）。
5. 对话中再按 **F** 结束对话。

| 操作 | 按键 | 说明 |
|---|---|---|
| 开始 / 结束对话 | **F** | 距 NPC 3 m 内按 F 开始；对话中再按 F 结束（`NpcDialogueTrigger.TalkKey` / `TalkRange`） |
| 说话 | **按住 V** | 按住录音、松开识别并发送；单句最长 25 秒，超时自动结束（`maxUtteranceSeconds`） |
| 打断朗读 | 对话中再**按住 V** | 立即停止播放并开始新一轮录音（barge-in），旧回复的迟到音频会被丢弃 |
| 取消这一句 | 录音中按 **Esc** | 丢弃当前录音与识别会话，不发送 |
| 打字输入 | **T** | 聚焦面板输入框；输入框最多 200 字 |
| 发送 | **Enter / 小键盘 Enter**，或点「发送」 | 提交输入框文本 |
| 取消输入 | 输入框聚焦时按 **Esc** | 输入框失焦；已输入的文字**不会清空**，再按 T 可继续编辑 |
| 结束对话（打字时） | 先按 Esc 退出输入，再按 F | 输入框聚焦时 `NpcDialogueTrigger` 会忽略 F，所以打字输入字母 `f` 不会误结束对话 |

补充行为（与代码一致）：

- 输入框聚焦时，V / T 被控制器忽略（不会一边打字一边录音）；F 被 `NpcDialogueTrigger.TextInputFocused()` 拦下。
- 对话中每帧检测与 NPC 的水平距离，超过 `TalkRange + 3 m`（默认 3 + 3 = 6 m）自动结束；
  对话期间玩家输入本就被禁用，主要防 NPC 位移 / 场景异常导致的「隔空对话」。
- NPC 每次回复都会朗读（`speakNpcReplies`），开场白同样朗读（`speakOpeningLine`，默认 true）。
- 玩家正在说下一句（录音 / 识别中）时，旧回复到达**只显示不朗读**，避免两个声音打架。
- 退出 / 场景切换时控制器销毁，录音、ASR、TTS 与播放全部清理。

## 4. 一轮对话链路

```
玩家按住 V
   │  MicCapture：麦克风采集 → 线性重采样为 16 kHz 单声道 PCM16（每帧一段）
   ▼
AsrClient ── WsConnection（Authorization: Bearer <百炼 Key>）──► /api-ws/v1/inference
   │  Paraformer realtime（run-task 协议）：
   │    task-started      → 补发连接建立期间缓存的预录音频
   │    result-generated  → 面板实时显示识别结果（提交前标「识别中」，heartbeat 帧忽略）
   │    松开 V → finish-task → task-finished 给出整句文本
   ▼
VoiceDialogueController.FinishUtterance → SubmitLine(text)
   ▼
NpcDialogueTrigger.SubmitPlayerLine
   │  写入历史「玩家：…」、GameEvents.RaiseNarrative、记行为日志 talk
   │  ReplyHandler(Spec, 玩家这句话, 此前历史)   ← GameBootstrap 注入
   ▼
NpcDialogueService.ReplyAsync → ILlmService.CompleteAsync（LLM）
   │  无 Key / 远端失败 / 超时 → 8 类 tag 的确定性兜底台词（永不抛异常）
   ▼
NpcDialogueTrigger.PublishNpcLine → ReplyReceived 事件
   ├─ VoiceDialoguePanel.SetNpcLine   面板显示（VoiceText.Flat 压成单行）
   └─ VoiceDialogueController.Speak
         │  VoiceText.SanitizeForSpeech：去括号动作描写 / Markdown / 表情
         ▼
      TtsClient ── WsConnection ──► /api-ws/v1/realtime?model=qwen3-tts-flash-realtime
         │  session.created → session.update（voice=Cherry, pcm, 24000 Hz）
         │  → input_text_buffer.append（整句）→ session.finish
         │  response.audio.delta（base64 PCM16）逐包到达
         ▼
      PcmPlayback.Feed → 可增长环形缓冲 → AudioSource 流式播放（24 kHz）
         │  缓冲 > 0.15 s 开始播；session.finished 且缓冲耗尽 0.5 s 后回到待命
         ▼
      面板状态回到「按住 V 说话，或按 T 打字」
```

### 4.1 控制器状态机（`VoiceDialogueController.VoiceState`）

| 状态 | 进入条件 | 面板状态文案（示例） |
|---|---|---|
| `Unavailable` | 启动 / 对话开始时缺 Key 或缺麦克风 | 「未配置语音 API Key：可打字对话（VoiceConfig.json / DASHSCOPE_API_KEY）」<br>「未检测到麦克风：按 T 打字输入」 |
| `Idle` | 待命 | 「按住 V 说话，或按 T 打字」 |
| `Recording` | 按住 V | 「录音中… 松开 V 结束」 |
| `Recognizing` | 松开 V、等待 `task-finished` | 「识别中…」 |
| `Thinking` | 已提交玩家发言、等待 NPC 回复 | 「思考中…」；超过 90 秒 →「NPC 回应超时，请重试。」 |
| `Speaking` | 收到 TTS 音频 | 「正在说话…（按住 V 可打断）」 |

面板状态色彩：待命灰蓝 / 聆听橙红 / 处理中金黄 / 说话亮蓝 / 出错红（`VoicePanelTone`）。

### 4.2 失败与兜底（实现细节）

| 情况 | 代码行为 |
|---|---|
| 无语音 Key 时按 V | `Fail("未配置语音 API Key，只能用键盘输入。", true)`：打印 warning，并自动聚焦输入框 |
| 无麦克风时按 V | `Fail("未检测到可用的麦克风，只能用键盘输入。", true)`：同上 |
| 麦克风启动失败 / 被占用 | `Fail("麦克风启动失败，只能用键盘输入。", true)` |
| ASR `task-failed` | 提示「语音识别失败：<服务端错误信息>」，并聚焦输入框 |
| 识别结果为空 | 「没有识别到语音，请再说一次或按 T 打字」 |
| ASR 连接先断开 | 由 `Recognizing` 状态兜底收尾（`FinishUtterance`），不会卡住 |
| TTS 连接失败（Key 无效 / 网络不通） | 「语音合成不可用，仅显示文字」，NPC 文本仍正常显示 |
| TTS 返回 `error` 事件 | 「语音合成失败：<错误信息>」 |
| 没有音频设备（如 `-batchmode` / 虚拟机） | 音频初始化只打 warning，不影响启动；打字对话仍可用 |
| NPC 回复超时 | 90 秒后「NPC 回应超时，请重试。」 |

## 6. 配置说明

### 6.1 `VoiceConfig.json` 字段

文件：`Assets/StreamingAssets/VoiceConfig.json`（`JsonUtility.FromJsonOverwrite` 读取，缺失字段保留内置默认值）。
字段名按 Unity 序列化规则区分大小写。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `apiKey` | `""` | 百炼（DashScope）Key，ASR 与 TTS 共用；**不要提交到公开仓库** |
| `asrUrl` | `wss://dashscope.aliyuncs.com/api-ws/v1/inference` | 语音识别 WebSocket 地址 |
| `asrModel` | `paraformer-realtime-v2` | 实时识别模型 |
| `asrSampleRate` | `16000` | 送进 ASR 的采样率（`MicCapture` 固定按 16 kHz 输出） |
| `ttsUrl` | `wss://dashscope.aliyuncs.com/api-ws/v1/realtime` | 语音合成 WebSocket 地址（`TtsClient` 会追加 `?model=`） |
| `ttsModel` | `qwen3-tts-flash-realtime` | 语音合成模型 |
| `ttsVoice` | `Cherry` | 音色名 |
| `ttsSampleRate` | `24000` | 合成音频采样率；`PcmPlayback` 与 `session.update` 用同一值 |
| `enableTts` | `true` | 总开关：false 时 NPC 回复只显示不朗读 |
| `ttsVolume` | `1.0` | 播放音量（0–1，`Range` 限制） |
| `pushToTalk` | `true` | **预留字段**：源项目用于「按住说话 / 常开 VAD」切换；当前只实现按住说话，常开 VAD 未启用 |
| `vadThreshold` | `0.012` | RMS 高于此值视为有人声；用于 `MicCapture.RmsThreshold` 与面板音量条归一化 |
| `silenceSeconds` | `1.1` | **预留字段**：原计划用于常开模式「句尾静音断句」，当前未使用 |
| `maxUtteranceSeconds` | `25` | 单句最长录音秒数，超时自动结束并发送（**生效**） |
| `micDevice` | `""` | 麦克风设备名；空 = 系统默认设备（实际为空时取 `Microphone.devices[0]`） |
| `sanitizeSpeech` | `true` | 朗读前是否清洗（括号动作描写 / 表情 / Markdown）；false 时只压成单行 |

### 6.2 Key 优先级（后者覆盖前者）

1. `VoiceConfig.cs` 内置默认值（`apiKey = ""`）
2. `Assets/StreamingAssets/VoiceConfig.json` 的 `apiKey`（本工程已配置，文档不写明文）
3. `PlayerPrefs` 键 **`EpicSpark.VoiceApiKey`**（游戏内临时换 Key 用，空字符串忽略）
4. 环境变量 **`DASHSCOPE_API_KEY`**（优先级最高，适合展示机 / CI）

实际生效来源会记在日志里：

```
[语音] 配置来源: <路径> [+ PlayerPrefs] [+ 环境变量DASHSCOPE_API_KEY] key=sk-**** ASR=... TTS=.../...
```

也可以从代码读：`VoiceDialogueController.Instance.ConfigSource` / `DescribeState()`。
日志只显示打码后的 Key（`VoiceConfig.MaskKey`：长度 > 10 时显示前 5 位 + `…` + 后 4 位；长度 ≤ 10 原样）。

**覆盖方式示例**

```csharp
// 游戏内临时换 Key（下次启动生效，或重启后仍保留）
PlayerPrefs.SetString("EpicSpark.VoiceApiKey", "<你的百炼 Key>");
PlayerPrefs.Save();
```

```powershell
# 启动 Unity 前在同一个 shell 里设置环境变量（优先级最高）
$env:DASHSCOPE_API_KEY = "<你的百炼 Key>"
```

### 6.4 降级行为一览

| 场景 | 表现 |
|---|---|
| 无语音 Key | 面板提示「未配置语音 API Key：可打字对话」；按 V 自动聚焦输入框并提示；**T 打字可正常对话**，NPC 回复只显示不朗读 |
| 无麦克风 | 面板提示「未检测到麦克风：按 T 打字输入」；其余同无 Key |
| Key 无效 / 欠费 / 无模型权限 | 面板提示「语音识别失败：…」或「语音合成不可用，仅显示文字」；文字对话不受影响 |
| 网络不通 / 代理拦截 | 同 Key 失效，状态不会卡死（TTS 连接失败会自行收尾，整体 90 秒兜底） |
| `enableTts=false` 或控制器 `speakNpcReplies=false` | NPC 回复只显示文字 |
| 没有音频输出设备 | 启动只打 warning；文字对话与 NPC 回复均正常 |
| LLM 不可用（与语音 Key 无关） | 回复走 `NpcDialogueService` 的确定性兜底台词，仍会朗读 |

## 7. 集成点与扩展方式

### 7.1 `NpcDialogueTrigger` 的对话 API

| 成员 | 类型 | 说明 |
|---|---|---|
| `ReplyHandler` | `static Func<NpcSpec, string, IReadOnlyList<string>, Task<string>>` | 由 `GameBootstrap` 注入，参数为 NPC 描述、玩家刚说的话、**此前**历史（不含当前这句）；为 null 时用本地降级文案 |
| `ReplyReceived` | `static event Action<NpcSpec, string>` | NPC 每说出一句（**含开场白**）时触发；`text` 已去掉「名字：」前缀，供面板显示与语音朗读 |
| `ConversationEnded` | `static Action<NpcSpec, List<string>>` | 对话正常结束，携带本轮完整历史；`GameBootstrap` 用它做第三人称摘要（记 `talk_summary`） |
| `ActiveConversation` | `static NpcDialogueTrigger` | 当前唯一进行中的对话（同一时间只允许一场） |
| `SubmitPlayerLine(string)` | `bool` | 玩家说一句（语音识别结果或键盘输入）：写入历史、广播叙事、异步请求 NPC 回复；不在对话中或内容为空返回 false |
| `IsAwaitingReply` | `bool` | 是否正在等待 NPC 回复（`SendCoreAsync` 中置 true，回复 / 结束时置 false）；供面板或外部读取 |
| `InConversation` / `History` | `bool` / `IReadOnlyList<string>` | 是否在对话、本轮历史（开场引导句 +「玩家：…」+「名字：…」） |
| `BeginConversation` / `EndConversation` / `AbortConversation` / `ToggleConversation` | `void` | 对话生命周期；`AbortConversation` 用于 NPC 倒地等异常，不触发 `ConversationEnded` |

实现要点（避免接入时踩坑）：

- 回复带**会话序号 + 请求序号**：玩家已经说了更新的一句时，旧请求的回复会被丢弃；对话结束后迟到回复直接忽略。
- 历史只把「此前」交给模型，玩家刚说的那句在提示词里单独给出；提示词侧只取最近 **10 行**、每行截断 120 字。
- `ReplyReceived` / `ReplyHandler` / `ConversationEnded` 都是**静态**的：订阅者必须在 `OnDisable` / `OnDestroy` 里取消订阅（控制器已 `-=`），`ReplyHandler` 全局只有一份，别直接覆盖别人的接线。

### 7.2 给别的角色 / 系统复用

**（1）让「当前对话」把某句话当成玩家发言（不走麦克风）**

```csharp
NpcDialogueTrigger trigger = NpcDialogueTrigger.ActiveConversation;
if (trigger != null && trigger.SubmitPlayerLine("我想打听一下城门的消息"))
{
    // 已提交，NPC 回复会通过 ReplyReceived 广播
}
```

**（2）旁听 NPC 每一句（做字幕、情绪、任务提示、语音以外的朗读方案）**

```csharp
private void OnEnable()  { NpcDialogueTrigger.ReplyReceived += OnReply; }
private void OnDisable() { NpcDialogueTrigger.ReplyReceived -= OnReply; }

private void OnReply(NpcSpec npc, string text)
{
    // text 是纯台词（无「名字：」前缀），可能含括号动作描写
}
```

**（3）无麦克风环境的文本通道（冒烟测试 / 自检 / 控制台调试）**

```csharp
VoiceDialogueController voice = VoiceDialogueController.Instance;
if (voice != null && voice.ConversationActive)
{
    voice.SubmitTextLine("你好，能告诉我今晚的口令吗？");
}
```

`SubmitTextLine(line)` 等价于 `SubmitLine(line)`，跳过录音与 ASR，其余链路（面板、NPC 回复、TTS 朗读）完全相同。

**（4）给别的角色加语音对话**

语音模块本身**不绑定具体 NPC**：它订阅的是全局 `ReplyReceived`，只对 `ActiveConversation` 响应。
因此任何 NPC 只要用 `NpcDialogueTrigger` + `NpcSpec` 走同一套对话即可自动获得语音能力，无需改语音代码。
若要换一种「会说话的对象」（非 NPC，例如旁白 / 无线电 / 系统播报），有两条路：

- 复用整条语音链路：`Speak` 是控制器的私有方法，最省事的做法是让该对象走 `NpcDialogueTrigger` 的对话流程
  （于是 `ReplyReceived` 会照常驱动面板与朗读）；
- 只要朗读：在脚本里组合 `TtsClient` + `PcmPlayback`（`VoiceConfig.Load(out source)` 取配置），
  文本先过 `VoiceText.SanitizeForSpeech`，音频包解码后 `PcmPlayback.Feed` 播放，参考控制器 `Speak` / `DrainTts` 的实现。

**（5）替换 NPC 大模型**

`ReplyHandler` 是唯一入口，`GameBootstrap.WireEvents()` 里指向 `OnNpcReplyAsync`（内部 `NpcDialogueService.ReplyAsync`）。
替换实现只需改这一处；若同时有其他系统也想接管，请用链式委托而不是直接覆盖。

### 7.3 控制器的公开状态

| 成员 | 说明 |
|---|---|
| `Instance` | 全局唯一实例（由 `GameBootstrap` 创建在 `VoiceDialogue` 对象上） |

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 按 V 没反应，面板提示「未配置语音 API Key」 | `VoiceConfig.json` 不存在 / 字段名拼错 / `apiKey` 为空；或覆盖用的 PlayerPrefs / 环境变量也是空 | 看 Console `[语音] 配置来源:` 与 `key=` 是否打码；确认 Key 是**百炼（DashScope）**的，不是 LLM 网关的 |
| 面板提示「未检测到麦克风」 | 系统隐私设置禁止麦克风、设备被禁用、远程桌面无音频重定向 | Windows 设置 → 隐私 → 麦克风，允许桌面应用访问；确认 `Microphone.devices` 非空；需要时在配置里固定 `micDevice` |
| 提示「麦克风启动失败」/ 音量条一直为空 | 其他软件独占麦克风（会议 / 直播 / 录音软件）、设备不支持 16 kHz 采集 | 关闭占用程序；换默认设备；检查设备「独占模式」；`MicCapture` 会做线性重采样，但设备本身要能启动 |
| DashScope 401 / 403 | Key 无效 / 过期 / 欠费 / 未开通对应模型，或 Key 与账号区域不匹配 | 到百炼控制台核对 Key 与 `paraformer-realtime-v2`、`qwen3-tts-flash-realtime` 的开通状态；错误信息会显示在面板状态行 |
| 按住 V 说话但“没有识别到语音” | 麦克风音量太低、选错设备、说话太短、VAD 阈值偏高 | 录音时看面板音量条是否有起伏；调低 `vadThreshold`（默认 0.012）或提高系统麦克风增益；一次说完整句再松开 |
| 识别结果总是慢半拍 / 只出中间结果 | 松开后立刻切走或脚本提前 Close 了 ASR | 正常应等待 `task-finished`；若自定义接入，别在 `Finish()` 后立刻销毁 `AsrClient`（控制器用 `Closed` 兜底收尾） |
| NPC 回复有字但没声音 | `enableTts` / `speakNpcReplies` 为 false；`ttsVolume` 为 0；系统静音；TTS 连接/鉴权失败；场景没有 `AudioListener`；`Camera.main` 为空 | 先看面板状态行是否提示「语音合成不可用 / 失败」；检查音量；控制器在启动时会尝试补一个 `AudioListener` 到 `Camera.main`，`Camera.main` 为空（无 MainCamera 标签）时需手动加 |
| 声音音调不对 / 变速 | TTS 实际采样率与 `ttsSampleRate` 不一致 | 保持 `ttsSampleRate = 24000`；不要只改 `PcmPlayback` 一侧 |
| 面板完全看不到 | 对话没开始（需 3 m 内按 F，且 `CanTalk`、玩家输入已启用）；其它 UI 遮挡（面板 Canvas 排序 110，HUD 为 10）；`GameBootstrap` 未运行（控制器没被创建） | 看 Console 是否有 `[语音] 对话开始：<NPC 名>`；确认场景里有 `GameBootstrap`；用 `VoiceDialogueController.Instance.ConversationActive` 与 `DescribeState()` 查状态 |
| 面板出现但 V / T 无响应 | 输入框仍在聚焦（正在打字）；玩家输入被禁用；对话已结束但面板未刷新 | 先按 Esc 退出输入；看 `DescribeState()` 的 `state` / `conversation` |
| 打字输入字母 f 就结束对话（已修复） | `NpcDialogueTrigger` 用 `TextInputFocused()` 检测输入框聚焦并跳过 F；若仍出现，说明焦点不在被识别的 `InputField` 上 | 确认面板输入框是当前 `EventSystem.currentSelectedGameObject` |
| 按住 V 打断后没有声音 / 状态短暂卡住 | barge-in 会关闭旧 TTS 会话并丢弃迟到事件，属正常；若持续超过 90 秒由超时兜底 | 观察 Console 是否有 `[语音]` 错误；检查网络与 Key |

日志关键字：`[语音]`（控制器）、`[语音自检]`（自检）、`[NpcDialogue]`（回复兜底与异常）。
行为日志里玩家发言仍记为 `talk`，对话结束摘要记为 `talk_summary`（沿用 NPC 模块，语音/打字来源不区分）。

## 10. 已知限制

1. **桌面 Windows 为主**：麦克风采集、`ClientWebSocket`、StreamingAssets 直读都按桌面实现；WebGL 不可用。
2. **Android / iOS 需改造**：`VoiceConfig.Load` 用 `File.ReadAllText` 直读 `StreamingAssets`，Android 上该路径在 apk 内不可直读，
   需改为 `UnityWebRequest`；麦克风权限也要运行时申请。
3. **依赖外网**：ASR / TTS 都要访问 `dashscope.aliyuncs.com`（WSS 443）；代理、证书拦截、企业网络会直接失败（已做失败降级）。
4. **TTS 是「整句合成」**：NPC 回复文本全部到齐后才 append 给 TTS 朗读，不是边生成边读；
   首字延迟 ≈ LLM 出完整回复的时间 + TTS 首包时间。
5. **两套 Key 相互独立**：ASR/TTS 用百炼 Key（本文档），NPC 回复用 F10 里配置的 LLM Key；只配一边时对应能力降级，不会报「配置错误」。
6. **常开麦克风 + VAD 自动断句未实现**：`pushToTalk` / `silenceSeconds` 是迁移保留字段，当前只有「按住 V 说话、松开识别」。
7. **面板只显示最后一句**：`SetPlayerLine` / `SetNpcLine` 各只有一行，长对话不会滚动保留（完整历史在 `NpcDialogueTrigger.History`）；
   长回复单行显示、不自动换行。
8. **提示词侧历史会被裁剪**：交给模型的是最近 10 行、每行 ≤120 字（`NpcDialoguePrompts.FormatHistory`）；
   完整历史只用于结束时摘要与外部读取。
9. **麦克风采集在主线程**：`MicCapture.Update` 里做重采样与 PCM 打包，高帧率下仍有少量 CPU 开销；不录音时不采集。
10. **Key 明文落盘**：`VoiceConfig.json` 是明文，PlayerPrefs 也是本机明文存储；**不要把带 Key 的工程或机器共享出去**，
    正式发行应改为服务端下发临时凭证。日志只会显示打码 Key。
11. **语音自检不验证真实链路**：自检只做静态/纯逻辑校验，不联网、不采集音频；真实 ASR/TTS 是否可用仍需在 Play Mode 里按住 V 实测。
